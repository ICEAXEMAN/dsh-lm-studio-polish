# LM Studio 文风润色

DSH 负责思考与执行，LM Studio 只负责「说话」。

## 它做什么

- 挂在模型流的出口（`llm/stream` waterfall）上，把主模型输出的**文本块**按段落切段，交给本地 LM Studio（OpenAI 兼容端点）做文风转写。
- 转写结果同时进入实时输出、会话日志与下一轮上下文——界面和历史是同一份文字，不会出现「看到的是润色版、存的是原文」。
- 推理块（reasoning）与工具调用参数一律原样透传，不参与润色。
- 旁路请求（会话标题 `purpose: session-title`、上下文压缩 `purpose: compaction` 等）不润色，只有普通对话请求会被处理。

## 保真红线

这些内容在**发送前**就被切走，模型根本看不到，也就改不坏：

- 围栏代码块、行内代码
- URL
- Windows 与 POSIX 绝对路径
- 数字、版本号

模型只看到自然语言段落，中间用 `⟦n⟧` 占位符代表被保护的片段。返回后逐个校验：占位符数量与顺序必须一致、长度不超过原文的设定倍率、不得出现档案里声明的禁用词、不得以「好的 / 以下是 / 当然」这类开场白起头、中英文不能串。任一项不过 → 一次修复重试 → 仍不过就用原文。

## 降级

超时、连不上、返回空、占位符丢失、校验不过、请求被中止——一律回放原文，本轮对话照常结束。LM Studio 连不上时会进入 15 秒冷却，期间直接跳过润色，避免每条都等一次超时。

## 左侧栏入口

- 左栏图标「文风润色」→ 主列页面（`main` 面板，key 与侧栏项同名）
- 设置 → 分区「文风润色」：同一页面，方便直达

页面提供：连接状态、LM Studio 地址与 API Key、模型列表与选择（来自 `/v1/models`，也可手填模型 id）、文风档案（新建/编辑/删除/切换）、长度倍率与跳过阈值、试跑、运行统计。

## 档案系统

三层，越往下权限越小：

1. **L0 硬规则** — 写死在代码里，档案改不到：只改表达不改事实、占位符原样、不加标题分点开场白、保持原语言、长度上限。
2. **L1 文风档案** — 可编辑：名称、文风（像谁在说话）、句式偏好、禁用词、追加要求。内置「自然口语 / 克制专业 / 温柔短句」三档。**禁用词与禁用句式用句号或问号分隔**（顿号、逗号属于句内成分，不当分隔符）。
3. **L2 场景** — 目前统一使用一个保守倍率（默认 1.15）；分段渐进时无法在发送前判断「这是解说还是终稿」，因此不冒险放宽。

## 模型选择与思考强度（重要）

润色只是一次短文本改写，**不需要推理能力**。但现在多数本地模型是思考型：先吐一大段 `reasoning_content` 再给正文，时间全花在思考上。

本机实测（同一段 12 字改写）：

| 配置 | 耗时 | 正文 |
|---|---|---|
| gemma-4-12b，模型默认（思考） | ~96 秒 | 有 |
| gemma-4-12b，`reasoning_effort: none` | **3.5 秒** | 有 |
| gemma-4-12b，`reasoning_effort: low` | 28 秒 | 无（被思考吃满） |
| deepseek-r1-0528-qwen3-8b（思考） | 23 秒 | 无 |
| qwen3.5-9b（思考） | 76 秒 | 无 |

所以插件默认发送 **`reasoning_effort: "none"`**（页面「思考强度」可改：none / low / medium / high / 不传）。模型或模板不接受该字段时，会**自动去掉字段重试一次**，不会因为一个请求参数丢掉整次改写。

结论：不需要特意去找非思考模型了，把思考强度设成 `none` 即可；真要更快，再考虑小的 instruct 模型。

## 时长与降级

- 单次超时默认 30 秒，页面可调到 300 秒（本机现设 120 秒，`reasoning_effort: none` 下实测 4–11 秒完成，余量充足）。
- 超时 / 连不上（进入 5 分钟冷却）/ 只有思考没有正文 / 占位符丢失 / 校验不过 → 一律回放原文。


## 配置文件

`$DSH_HOME/lm-studio-polish.json`：`enabled / baseUrl / model / apiKey / timeoutMs / minChars / maxRatio / wholeBlock / profileId / profiles`。
日志：`$DSH_HOME/lm-studio-polish.log`。


## 其他插件生成的文字（B 站等）

插件自己的「工具型补全」——例如 B 站插件的动态、日记、私信草稿——不是会话回合，没有 `sessionId`。这一层默认也接管（`polishForeign` 开关）：

- **数据一律不动**：以 `{` `[` `<` 开头，或 ```json/```yaml/```csv 围栏开头的文本，直接透传，连模型都不调（JSON 被改写会打断解析）。
- **预算更紧**：其他插件的调用通常只有 30 秒上下，所以单独的 `foreignTimeoutMs`（默认 20 秒）会取 `min(单次超时, foreignTimeoutMs)`。
- **慢模型自动跳过**：一旦实测这类调用已经超过预算的 75%，后续直接跳过（`slow-model`），不再每条白等。
- 想要真正生效，把模型换到能在 10 秒内出结果的那档（例如 gemma-4-12b + 思考强度 `none`，实测 3.5 秒）。

关闭方式：页面「也润色其他插件生成的文字」取消勾选，或配置 `polishForeign: false`。

## 已知限制

- **润色稿会进入历史**：下一轮主模型看到的是润色后的文字。这是「在生成时改写」的固有代价，也是它能落进日志的原因。想完全不改历史，只能在页面里做只读预览。
- **首字延迟**：分段渐进模式下，第一段润色完成才出字；短句、代码块、少于阈值（默认 24 字）的片段直接透传，不受影响。「整段一次」开启时，整段结束后才会出现文字。
- **并发**：宿主侧串行处理（上限 1），多会话时后到的请求排队。
- **replayState**：发生过改写的请求会丢掉 `finish.replayState`，避免提供方的块级回放和改写后的文本对不上。
- 页面使用的是 loopback HTTP 路由（`/api/lm-studio-polish/v1/*`），与 DSH 自身的 RPC 通道无关；仅本机可访问。
